# Growth playbook — toward a top GitHub antidetect resource

This doc is for maintainers. The repo is structured for **discoverability** and **trust**; stars follow distribution.

## 1. GitHub repo settings (do once)

- **Description:** `Open antidetect ops lab — benchmarks, JSON datasets, free tools, evidence-first playbooks`
- **Website:** `https://multilogin-labs.github.io/`
- **Topics:** `antidetect-browser` `browser-automation` `fingerprinting` `playwright` `multilogin` `benchmark` `github-pages` `open-data` `devtools` `web-scraping`
- Pin **CATALOG.md** or README in social preview
- Enable **Issues** and **Discussions** (Q&A category: “Benchmark requests”)

## 2. What makes this repo “#1 worthy”

| Lever | Action |
|-------|--------|
| **Unique data** | Publish `benchmark-matrix-YYYY-MM.json` every month; never scrape competitors’ text |
| **Awesome lists** | PR to `awesome-*` repos linking **CATALOG.md**, not homepage alone |
| **Reddit / forums** | Share methodology + dataset curl one-liner, not coupon codes |
| **YouTube / LinkedIn** | 5-min “how we score Band A” using live tools |
| **CI green badge** | Keep `.github/workflows/ci.yml` passing — shows professionalism |

## 3. Content cadence (suggested)

- **Monthly:** benchmark matrix JSON + short report HTML
- **Quarterly:** methodology changelog entry
- **Ad hoc:** new snippet when MLX API surface changes (link official docs)

## 4. SEO (Google)

- Submit `sitemap.xml` in Search Console after each structural change
- Request indexing for new `/data/*.json` files (unique assets index well)
- Avoid re-adding per-vendor thin pages

## 5. Metrics to track

- GitHub stars / forks / traffic (Insights)
- Search Console impressions for “antidetect benchmark”, “fingerprint readiness”
- Tool page engagement (readiness score completions if you add lightweight analytics later)

## 6. Do not

- Buy stars or use bot traffic (GitHub ToS + destroys trust)
- Re-add MLX doc mirrors for “more pages”
- Copy pricing tables from vendors without verification date
